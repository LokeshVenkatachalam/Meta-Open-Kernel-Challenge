01 · Problem

What this kernel asked for.

Attention decode has a small preparation boundary around a much larger paged attention reduction. The retained source beat SGLang by 1.151975903562266x while preserving dense visibility, scaled-cache, and live-slot semantics.

The final public snapshot placed the result 1278 of 1379, behind a provisional 3.3389x leader.

02 · Retained approach

What survived the campaign.

One Triton preparation kernel fuses Q/K RMS normalization, optional interleaved RoPE, FP8 query conversion, and scaled K/V cache insertion.

The retained path uses fixed uniform-query shapes where valid and reuses compatible scheduler metadata so FlashAttention-3 avoids an extra prepare step.

03 · Measured lessons

What the numbers taught us.

Removing launch and metadata overhead helped verify and sliding-window shapes, while full B16/B32 attention remained dominated by the FlashAttention-3 main kernel.

The fixed-query metadata variant produced the strongest check at 1.1525x and the retained score at 1.1520x.

Several small point-estimate changes had overlapping confidence intervals and were not treated as proven improvements.

04 · Experiments that did not survive

Regression is part of the record.

The first fused preparation failed compilation because Triton constants were not constexpr, so it has null performance fields in the public ledger.

A correct custom split-KV Triton gather reached only 0.3974x; random page-1 gathers and small matrix tiles did not replace the Hopper-native attention kernel effectively.

05 · Boundaries

Where this result stops.

The fixed-query choice depends on the challenge's uniform query lengths and exact cache contract.

The ranking is provisional, and this result did not approach or surpass the public leader.
