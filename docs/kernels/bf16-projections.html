01 · Problem record

What the measured workload asked for.

This workload mixes low-M BF16 GEMMs with a router path whose FP32 weights are represented as BF16 high and low parts. The retained scored source beat SGLang by 1.131876248733277x on the hosted H200 judge.

The campaign improved from a first scored result near 1.1081x, but remained below the provisional 1.7277x leader.

02 · Published approach record

What the agentic workflow submitted.

Dispatch uses a pinned Hopper BF16 GEMV path for selected M=1 projections, custom split-K kernels for profitable pooler and sliced-unpooler shapes, and the official SGLang dispatch elsewhere.

The router preserves BF16 high-plus-low weight semantics, accumulates in FP32, uses full-M tiles, and stores partials split-major for contiguous reduction traffic.

Originality caveat: this approach description is not a certification that the implementation was independently authored.

03 · Measured lessons

What changed in the archived measurements.

Changing router partials from output-major to split-major removed a measured strided-reduction penalty.

The profitable custom cutovers were narrow: pooler through M=8 and the sliced N=1024 unpooler.

The highest campaign check used a different candidate than the retained scored source, so best check and paired source check are reported separately.

04 · Recorded regressions

Experiments that did not survive measurement.

A direct scalar Triton reduction reached only 0.4877x, and a low-split BF16 attempt reached 0.8161x.

Replacing the workspace reduction with FP32 atomics passed correctness but regressed to 1.1134x because contention hurt larger router shapes.

05 · Boundaries

Where this result claim stops.

The retained dispatch is shape-specific and was measured only through the official challenge shape set on a hosted NVIDIA H200.

Rank 1510 of 1746 is a provisional public snapshot, not a final award or leaderboard win.
