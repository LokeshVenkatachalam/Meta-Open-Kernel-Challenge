Measurement notes

How the evidence was made.

Local development used only CPU-side Linux tools. GPU execution, correctness checks, and timing happened through the challenge's hosted NVIDIA H200 workflow. The distinction shapes every claim on this site.

Hardware: NVIDIA H200Campaign: 79 attemptsStatus: closed

Hosted workflow

Code moved to the GPU; raw infrastructure did not move into this publication.

  1. 1

    Develop locally

    Kernel source and experiment hypotheses were prepared on Linux with localGpuUsed: false. No local timing is presented as H200 evidence.

  2. 2

    Run a hosted check

    Checks tested correctness and returned off-board timing evidence when available. They supported iteration but did not set leaderboard placement.

  3. 3

    Submit a scored run

    Scored runs produced the retained publication metrics: measured microseconds, scored baseline, speedup, and a 95% confidence interval.

  4. 4

    Freeze source and snapshot

    The retained file was hashed, associated with a passing check, and compared with a timestamped leaderboard snapshot after the track closed.

Check vs scored

Two modes answer different questions.

Check

Did this candidate pass the hosted evaluator, and what timing evidence was returned? The site reports the highest passing campaign check separately. It can differ from the check paired to the exact retained source.

Scored run

What result was placed on the scored path? The five headline values—1.131876×, 1.151976×, 1.340289×, 1.185588×, 1.919190×—come from verified scored jobs, not cherry-picked checks.

Uncertainty

A confidence interval is a range, not a trophy.

Each 95% interval summarizes the evaluator's reported uncertainty around speedup. Narrower is more precise; overlap does not by itself prove a tie, and separation does not make the result portable to other shapes or hardware.

Use the interval

Read the point estimate with both bounds. This site never replaces a missing interval with a guessed one.

Keep modes separate

A fast check is useful evidence, but only a scored run supports the displayed scored result and provisional rank.

Keep the denominator visible

Speedup compares the evaluator's scored baseline with measured kernel time for that problem and run.

Limitations

What these numbers do not establish.

  • Hardware specificity. Measurements come from the hosted NVIDIA H200 path; they are not local benchmarks or guarantees for other accelerators.
  • Workload specificity. A retained implementation can be excellent for judged shapes while leaving other shapes, batching regimes, or concurrency patterns unexplored.
  • Runtime specificity. Compiler, driver, evaluator, and scheduling conditions are pinned to the hosted environment and may change outside the archived campaign.
  • Leaderboard timing. Rank, placed count, and leader speedup are provisional values captured at 5 Nov 2026, 20:28:37 UTC.
  • Campaign selection. The experiment table contains all 79 in-scope attempts, including failures, but not the 13 account runs outside the defined campaign.
